サブエージェントの行やフォルダは展開できます。右タブ案では「概要・サブエージェント・ファイル」を切り替えられます。どちらもサンプル表示です。

サブエージェント

$.agent.list() で今のセッションの名前・タスク・状態を表示する。まず行を開いて概要を読む。会話を切り替えるなら明示的な「会話を開く」と「本編に戻る」を用意する。端末で $.ui.view() を使うと入力先も変わるため、展開や選択だけでは呼ばない。

フォルダツリー

現在の worktree を起点に、フォルダを開くと直下の階層を読む。最初は名前と読み取りプレビューだけ。あると便利なのは、Git の変更印と「変更ありだけ見る」切り替え。

Mod 単体なら、まず右側のタブで中身を作れる。 公開 Mods API の CLI ペインは右か入力欄の上で、独立した左ペインの指定はできない。左右を同時に常駐させる構想では、tmux など外側で左を描く UI と、現在のセッションの状態をそこへ渡す仕組みが別に必要。

02 / OVERVIEW

まず見えるようにする3つ

環境

リポジトリ、現在のブランチ、作業フォルダを表示。$.session.cwd() と Git から取得する。worktree を使っているなら、実際の作業先が分かるようにする。

コンテキスト

普段は $.session.usage() の使用数・上限・割合。展開したときはカテゴリ別の推計と項目の詳細を表示する。計測値が来るまでは未計測。

変更

現在のブランチの PR を gh pr view --json で取得。PR の追加・削除と CI、作業ツリーの未コミット差分を別々の行に出す。

›コンテキストの内訳をつなぐ
  • 展開時に $.session.usage({ breakdown: "summary" }) を試す。公開型定義上はローカル推計。取得できない版では合計だけを残し、/context を案内する。
  • 展開中の使用率・行・バーは、同じ内訳の rawMaxTokens を分母にそろえる。普段の表示と推計の数字が異なる場合がある。
  • used・buffer・free は色を分ける。deferred は表には出すが、使用量やバーには足さない。
  • 項目の一覧は返却データがある場合だけ展開できるようにする。右のカスタムエージェントは定義、左のサブエージェントは実行状況。

端末幅が足りないときは入力欄の上へ。 配置は Claude Code に任せ、Mod 側は dock なら全体、inline なら短い表示に切り替える。CLI での幅やフォーカスの挙動は初回の実機確認に含める。

03 / VIEW MENU

「ビュー」から何を開くか

Desktop と同じ並びで、環境・コンテキストとは別のメニューを開く。右端には CLI のコマンドや動作を出し、キー割り当ては実機で競合を確認してから決める。

各メニュー項目の動作と実装範囲
表示選んだときの動作
変更作業ツリーの差分は /diff。PR カードは詳細を表示し、PR 全体の差分は GitHub で開く。最初に接続する操作。
ブラウザPR や明示的に指定した URL を外部ブラウザで開く。埋め込みは対象外。
ファイル探索のファイルツリーを開き、ファイルを選んで読み取りプレビュー。後続。エディタは含めない。
ターミナルtmux 使用時に同じ作業フォルダで別ペインを開く。後続。tmux がなければ非対応として表示。
サイドチャット/btw で本編に混ぜずに質問する。後続。下書きを上書きしない動線を確認。
背景タスク/tasks で今のセッション内のバックグラウンド作業を確認する。後続。他セッションの一覧は出さない。
04 / BUILD ORDER

作る順番

初版のゴールは、3つの概要を会話の横で見られることと、変更の詳細に進めること。

  1. 01

    固定データで描く

    /rail で $.ui.open を呼び、ui.render で自分の Pane だけ描く。開閉と狭い端末の配置を確認。

  2. 02

    セッションと Git

    作業先、コンテキストの合計、手元の差分を接続。内訳は折りたたみとして後から検証する。

  3. 03

    PR カードを追加

    手元の情報を先に出し、PR 情報を後から差し込む。PR なし、取得失敗、CI 実行中を区別する。

  4. 04

    ビューを開く

    変更の導線からつなぐ。ボタンからの /diff 起動は実機で確認し、難しければコマンドを案内する。

その次は探索。 サブエージェントの一覧とファイルツリーを、まず右ペイン内で切り替えられるようにする。両方を見ながら作業したくなったら、左常駐のための外側 UI を検討する。

›初版の動作確認
  • 幅のある fullscreen では会話の右に表示され、狭い場合は入力欄の上に出る。
  • 開閉と Tab / Enter で操作でき、会話の入力に戻れる。
  • コミット後は未コミット差分だけが減り、PR の差分行数は独立して表示される。
  • PR なしと取得失敗を別表示にする。GitHub に接続できなくても作業ツリーとコンテキストは確認できる。
  • 内訳を開閉しても会話の入力に戻れる。遅延読み込みの項目は使用量を増やさない。
  • 同じリポジトリの別 worktree で、現在のブランチとフォルダが表示される。

CLI 向けの設計案です。プレビューはブラウザ用のモックで、端末の色や文字幅とは異なります。
